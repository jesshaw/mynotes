# redis

## Redis 工作原理

Redis（Remote Dictionary Server）是一个基于内存的 NoSQL 数据库，采用 Key-Value 结构存储数据，支持多种数据结构，并提供持久化、发布/订阅、Lua 脚本等功能。其核心工作原理如下：

### 1. 内存存储

Redis 使用 **内存** 存储数据，读写速度极快，适用于高并发场景。

默认使用 **SDS（Simple Dynamic String）** 作为字符串存储结构，比 C 语言的 `char*` 具有更好的性能和安全性。

### 2. 数据结构

Redis 提供丰富的数据结构：

- **String（字符串）**：最基础的数据类型，存储简单键值对。
- **List（列表）**：基于双向链表，适用于消息队列、排行榜等。
- **Set（集合）**：无序集合，支持去重、交集、并集等操作。
- **Hash（哈希）**：适用于存储对象（如用户信息）。
- **Zset（有序集合）**：带权重的集合，常用于排行榜。

### 3. 持久化

Redis 提供两种持久化方式：

- **RDB（Redis Database）**：以快照的方式存储数据，定期保存数据到磁盘。
- **AOF（Append Only File）**：记录每一条写操作，保证数据的持久性。

### 4. 事件驱动

Redis 使用 **Reactor 模式**，基于 **单线程 + I/O 多路复用**，处理并发请求，避免线程切换开销。

### 5. 过期与淘汰策略

**过期策略**：

- **定期删除**（每隔一段时间随机抽样删除部分过期键）。
- **惰性删除**（访问数据时检查是否过期，过期则删除）。

**淘汰策略**：

- **volatile-lru**：从设定了过期时间的数据集中淘汰最近最少使用（LRU）的数据。
- **allkeys-lru**：从所有数据集中淘汰最近最少使用的键。
- **volatile-random**：从设置了过期时间的数据集中随机淘汰数据。
- **allkeys-random**：从所有数据集中随机淘汰数据。
- **volatile-ttl**：优先淘汰即将过期的数据。
- **noeviction**：不淘汰数据，写满时报错。

### 6. 分布式架构

- **主从复制**（Master-Slave）：提高读取能力，主节点写，多个从节点读。
- **Sentinel**（哨兵）：实现高可用，自动故障转移。
- **Cluster**（集群）：采用槽（Slot）分片，提高扩展性。

## Redis 常见面试问题

### 1. Redis 和 Memcached 的区别？

| 特性 | Redis | Memcached |
|------|------|------|
| 数据结构 | 支持多种数据结构 | 仅支持 Key-Value |
| 持久化 | 支持 RDB 和 AOF | 不支持 |
| 过期策略 | LRU、TTL、惰性删除等 | LRU  |
| 事务 | 支持（MULTI、EXEC） | 不支持 |
| 发布订阅 | 支持 | 不支持 |
| 集群模式 | 支持 | 依赖客户端分片 |
| 数据大小 | 更适合复杂场景 | 适用于小数据存储 |

### 2. Redis 为什么是单线程的？

- Redis 采用 **单线程 + I/O 多路复用** 处理请求，避免线程切换的开销。
- 由于 Redis 的操作大多是**内存操作**，瓶颈不在 CPU，而在 **网络和内存访问**。
- 实测 Redis 的 **QPS 可达 10 万级别**，性能足够高。

### 3. Redis 持久化方式有哪些？各有什么优缺点？

| 持久化方式 | RDB（快照） | AOF（日志） |
|------------|-------------|-------------|
| 触发方式 | 定期保存 | 记录每次写操作 |
| 性能 | 低，影响较小 | 高，影响较大 |
| 数据完整性 | 可能丢失部分数据 | 丢失数据较少 |
| 文件大小 | 小 | 大 |
| 适用场景 | 适用于冷备、故障恢复 | 适用于实时数据同步 |

- **最佳实践**：开启 **RDB + AOF**，AOF 采用 **everysec**（每秒刷盘）。

### 4. Redis 分布式架构有哪些？

- **主从复制（Master-Slave）**：数据复制，读写分离，提高性能。
- **哨兵（Sentinel）**：监控主从节点，自动故障转移。
- **Redis Cluster**：支持水平扩展，无中心化架构，采用**哈希槽**（16384个 slot）分片。

### 5. Redis 事务是如何实现的？

Redis 事务通过 **MULTI、EXEC、DISCARD** 进行。

**事务特性**：

- **原子性**：同一事务内的命令按顺序执行，不会被其他请求打断。
- **但不支持回滚**，如果事务执行中某条命令失败，Redis 仍会执行剩余命令。

### 6. Redis 如何防止缓存击穿、缓存穿透、缓存雪崩？

**缓存穿透**（请求的数据不存在）：

- 方案：使用 **布隆过滤器** 或 **缓存空值**。

**缓存击穿**（热点 Key 失效，大量请求打到数据库）：  

- 方案：**设置热点 Key 永不过期**，或使用 **互斥锁**。

**缓存雪崩**（大量 Key 同时失效，DB 瞬间压力巨大）：  

- 方案：**设置随机过期时间**，防止集中失效。

### 7. Redis 如何实现分布式锁？

- **SET key value NX PX 3000**（PX 代表过期时间 3000ms）
- **Redlock**（官方分布式锁方案）：基于多节点实现。

### 8. Redis 为什么快？

- **纯内存操作**，无磁盘 I/O。
- **单线程 + I/O 多路复用**，无锁争抢。
- **高效数据结构**（如哈希表、跳表）。
- **管道（Pipeline）** 批量操作减少网络开销。

### 9. Redis Zset（有序集合）底层数据结构？

- **跳表（SkipList）** + **压缩列表（ZipList）**
- **跳表** 用于存储较大数据集，支持 O(logN) 查找。
- **压缩列表** 用于小数据存储，节省内存。

### 10. Redis 如何解决大 Key 问题？

- **拆分大 Key**：改为多个小 Key 存储。
- **Lazy delete**：异步删除，防止阻塞。
- **Bigkey 监控**：使用 `redis-cli --bigkeys` 定期检查。

## 总结

Redis 作为高性能的缓存数据库，凭借 **内存存储、丰富数据结构、持久化机制、分布式架构** 等特性，广泛应用于**缓存、分布式锁、排行榜、消息队列**等场景。面试中，重点掌握其 **原理、数据结构、持久化、事务、分布式架构** 及 **优化方案**，才能脱颖而出！
